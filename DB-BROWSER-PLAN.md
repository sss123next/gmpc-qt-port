# Переработка раздела Database

Цель: вместо нерабочего одиночного списка — обзор базы, пригодный для навигации
и действий. Оригинальный gmpc (tag2-browser) взят как источник идей, но не как
шаблон: каскад колонок с поиском в каждой панели заменён на master-detail.

## Целевой макет

```
┌ Browse by: [Artist ▾]  Filter artists and albums… ┐
├───────────────────────────┬───────────────────────┤
│ Artist      Tracks · Time │ [обложка] Название    │
│ + Tool        169  17 h   │           Подпись     │
│   ├ Ænima       8   51 m  │           8 трэков …  │
│   └ Lateralus   2   12 m  │ Filter tracks…        │
│                           │ # Title Time Artist … │
└───────────────────────────┴───────────────────────┘
```

- Слева дерево групп и альбомов: серверные счётчики, ленивая загрузка
  альбомов при раскрытии, фильтр по именам.
- Справа всегда видимая таблица трэков выбранного узла (не теряется при
  переключении), шапка с обложкой и объёмом, собственный фильтр.
- Действия — существующие `BrowserIntent`, меню собирает MainWindow.

## Журнал

### 2026-11-19 — разведка
Оригинальный gmpc держит каскад genre|artist|album с поиском в каждой панели.
`count group <TAG>` отдаёт все значения тега со `songs:`/`playtime:` одним
ответом; на базе 1825 артистов — ≈20 мс. Пустое значение приходит как `""`
и является легальной группой «без тега».

### 2026-11-23 — реализация и проверка
Собраны транспорт, обе модели, виджет и проводка; написаны юнит- и live-тесты.
Полный ctest: 37/37 без MPD и 100 % на одноразовом сервере с мутациями.

Визуальная приёмка вскрыла три дефекта раскрытия, которых не видели тесты:

1. `QSortFilterProxyModel` по умолчанию отвечает «да» на `canFetchMore`, но
   `fetchMore` ничего не делает — добавлены явные переопределения с
   `mapToSource()`.
2. Вид вообще не спрашивал `canFetchMore`: базовый `hasChildren()` для группы
   без загруженных детей отвечает «нет», поэтому стрелка раскрытия не
   рисовалась и узел оставался свёрнутым навсегда. Переопределён
   `MusicDatabaseModel::hasChildren()` (истина, пока есть что грузить).
3. Загрузка дополнительно привязана к сигналу `QTreeView::expanded`, чтобы не
   зависеть от того, успел ли вид спросить модель до отрисовки.

Раскладка: колонка счётчиков в дереве получила фиксированную ширину по своей
подписи (обрезалась), заголовки таблицы выровнены по левому краю
(центрирование читалось как пустая колонка).

### Остаток
- Группы грузятся синхронно при подключении и смене группировки: на очень
  большой базе это заметная пауза (счётчики дешёвые, но список длинный).
